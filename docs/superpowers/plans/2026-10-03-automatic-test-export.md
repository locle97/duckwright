# Automatic Test Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `duckwright export runs/<id>` turns a successful run's `history.json` into a ready-to-run `@playwright/test` `.spec.ts`, and `duckwright --export "<task>"` does the same automatically at the end of a successful run.

**Architecture:** A new standard-library module, `duckwright/export.py`, loads and validates `history.json`, renders the recorded `code` lines into a spec file, and writes it. `__main__.py` gets two entry points onto it: an `export` subcommand, dispatched when `argv[0] == "export"` before the run parser sees it (the run parser keeps its positional `task`, so existing invocations are unchanged), and a `--export` flag on the run that calls the same function after `history.json` is written.

**Tech Stack:** Python ≥3.11 standard library; pytest. Generated output targets Node.js `@playwright/test`.

**Spec:** No separate spec file. The requirement is the README roadmap line: "**Automatic test export**: `python3 -m duckwright export runs/<id>` writes a ready-to-run `.spec.ts` from `history.json`, replacing the manual [regression test](#turning-a-run-into-a-regression-test) steps", plus the user's addition: "With `--export`, the test would be generated after running."

## Decisions (made here; do not re-litigate)

- **Input:** `export` accepts a run directory or a path to a `history.json` file.
- **Output:** `<run-dir>/duckwright.spec.ts` by default; `-o/--output FILE` overrides it (parent directories are created). An existing file is overwritten, so re-exporting is idempotent.
- **Only successful runs export.** `success: false` (done failure, max steps, interrupted, errors) is refused: a test built from a failed run encodes the failure.
- **Which lines go in:** every action's non-null `code`, in step order, except `screenshot` actions (their code writes a file into the session's output dir and asserts nothing).
- **Multi-line code** is kept and every line indented by two spaces.
- **Test title** is the task, written as `json.dumps(task, ensure_ascii=False)` (a valid JS string literal for any input).
- **Tab commands** (`tab-new`, `tab-select`, `tab-close`) whose result was `ok` produce a `// TODO(duckwright): <cmd> needs a hand edit; this test assumes a single page` line at that position (cmd name only, never args) plus a warning. Generating real multi-tab code is the separate roadmap item "Multi-tab and storage state in exports" and is out of scope, as is recording `--state` in `history.json`.
- **No recorded assertions** still exports, with a warning.
- **Exit codes for `export`:** `0` written, `1` refused (run failed, nothing to export), `2` input unusable (path missing, not JSON, wrong shape). Matches the run's existing `1`/`2` meanings.
- **`--export` never changes the run's exit code.** On success it prints `Test: <path>`; if the export itself fails it prints `export failed: <msg>` to stderr and the run still exits `0`. On a failed run it prints `Test: not exported (run did not succeed)`.
- A task that is literally the single word `export` can no longer be run; documented in the README.

## Global Constraints

- Runtime stays standard-library only (`dependencies = []`).
- Spec file layout, exactly (blank lines included):
  ```ts
  // Generated by duckwright from history.json. Review before committing:
  // recorded code contains everything the agent typed, passwords included.
  import { test, expect } from '@playwright/test';

  test(<json-encoded task>, async ({ page }) => {
    <code lines, two-space indent>
  });
  ```
  ending with a single trailing newline.
- Warnings go to stderr, one per line, prefixed `warning: `.
- No traceback ever reaches the user from `export`; every failure is an `ExportError` with a message.

## Review Focus

1. **A task containing quotes, backslashes, newlines or `*/`.** Expected: the title is still one valid JS string literal and the header comments are untouched. Pinned by Task 1 `test_title_is_json_escaped`.
2. **A bad path or a damaged `history.json`** (missing, a directory without `history.json`, invalid JSON, a JSON list, `history` missing or not a list). Expected: exit `2`, a one-line message, no traceback. Pinned by Task 1 `test_load_history_rejects_bad_input` (parametrized) and Task 2 `test_export_bad_path_exits_2`.
3. **A run that "succeeded" with no recorded code** (e.g. a single `done success` answering from the first snapshot). Expected: refused with exit `1`, `nothing to export`, and no file written. Pinned by Task 1 `test_nothing_to_export_is_refused`.
4. **Tab-command args containing a newline.** Expected: the TODO line names only the command, so no arg text can escape a `//` comment. Pinned by Task 1 `test_tab_command_marks_todo_without_args`.
5. **`--export` when the export step itself fails after a successful run.** Expected: the run still exits `0`, `history.json` is written, and stderr says `export failed:`. Pinned by Task 2 `test_run_export_failure_keeps_exit_0`.

### Task 1: `export.py`, which loads a run and renders the spec

**Files:**
- Create: `duckwright/export.py`
- Test: `tests/test_export.py`

**Interfaces:**
- Consumes: the `history.json` shape written by `duckwright/__main__.py:_history_json` (`task`, `success`, `answer`, `steps`, `cost_usd`, `history[].actions[].{cmd,args,code}`, `history[].results[]`).
- Produces:
  - `SPEC_NAME = "duckwright.spec.ts"`
  - `class ExportError(Exception)` with `__init__(self, message: str, exit_code: int)` and attribute `exit_code: int` (`1` refused, `2` bad input).
  - `load_history(path: Path) -> tuple[Path, dict]`: returns `(run_dir, data)`. `path` may be a run dir or a `history.json` file. Raises `ExportError(..., 2)` when the file is missing, is not JSON, is not an object, lacks a `str` `task`, a `bool` `success`, or a `list` `history` whose items are objects with a `list` `actions`.
  - `render_spec(data: dict) -> tuple[str, list[str]]`: returns `(spec_text, warnings)`. Raises `ExportError("run did not succeed; only successful runs can be exported", 1)` and `ExportError("nothing to export: the run recorded no Playwright code", 1)`.
  - `export_run(path: Path, out: Path | None = None) -> tuple[Path, list[str]]`: load, render, write to `out or run_dir / SPEC_NAME` (creating parents), return the written path and the warnings.

- [ ] **Step 1: Write the failing tests** in `tests/test_export.py`

Build histories with a small helper so each test states only what matters:

```python
def step(*actions, results=None):  # actions: (cmd, args, code)
    acts = [{"cmd": c, "args": a, "code": k} for c, a, k in actions]
    return {"step": 0, "evaluation_previous_goal": "", "memory": "", "next_goal": "",
            "actions": acts, "results": results or ["ok"] * len(acts)}

def run(*steps, task="greet", success=True):
    return {"task": task, "success": success, "answer": "", "steps": len(steps),
            "cost_usd": 0.0, "history": list(steps)}
```

Tests (names and assertions):

- `test_renders_exact_spec`: a run with `goto` (`await page.goto('https://example.com/form');`), `fill`, `click`, `expect` (`await expect(page.getByText('Hello, Linh!')).toHaveText("Hello, Linh!");`) and `done` (code `None`) renders exactly the Global Constraints layout with those four lines in order, title `"greet"`, and `warnings == []`.
- `test_skips_null_code_and_screenshot`: a `click` with `code: None` and a `screenshot` with non-null code do not appear in the output.
- `test_multiline_code_is_indented`: code `"await a;\nawait b;"` renders as `"  await a;\n  await b;\n"` inside the body.
- `test_title_is_json_escaped`: task `'say "hi"\\ */ \nnow'` → the `test(` line is `test(` + `json.dumps(task, ensure_ascii=False)` + `, async ({ page }) => {`, and the first two lines of the output equal the fixed header.
- `test_failed_run_is_refused`: `success=False` → `ExportError` with `exit_code == 1` and `"did not succeed"` in the message.
- `test_nothing_to_export_is_refused`: a successful run whose only action is `done` → `ExportError`, `exit_code == 1`, `"nothing to export"`; `export_run` on it leaves no `duckwright.spec.ts` in the run dir.
- `test_no_assertions_warns`: a run with code but no `expect` code → warnings contain `"no assertions recorded; add expect(...) lines by hand"`.
- `test_tab_command_marks_todo_without_args`: a `tab-new` action with args `["https://x\nawait evil();"]`, code `None`, result `"ok"` → output contains `"  // TODO(duckwright): tab-new needs a hand edit; this test assumes a single page\n"`, does not contain `"evil"`, and warnings contain `"run used tab-new; edit the test by hand, it assumes a single page"`. A `tab-new` whose result starts with `error:` adds neither.
- `test_load_history_accepts_dir_and_file`: both `run_dir` and `run_dir / "history.json"` return `(run_dir, data)`.
- `test_load_history_rejects_bad_input` (parametrized): missing path; directory without `history.json`; file containing `not json`; file containing `[]`; object without `history`; `history` that is a dict; `success` that is the string `"true"` → each raises `ExportError` with `exit_code == 2`.
- `test_export_run_default_and_custom_output`: default writes `run_dir / "duckwright.spec.ts"`; `out=tmp/"a"/"b"/"x.spec.ts"` creates `a/b` and writes there; the returned path is the written one; a second call overwrites without error.

- Test: `tests/test_main.py`

**Interfaces:**
- Consumes: `export_run`, `ExportError`, `SPEC_NAME` from Task 1.
- Produces:
  - `_parse_export(argv: list[str]) -> argparse.Namespace` with `prog="duckwright export"`, positional `run` (help: `run directory or history.json`), `-o/--output FILE`.
  - `_export_main(argv: list[str]) -> int`: prints `Test: <path>` to stdout and each warning as `warning: <w>` to stderr; on `ExportError` prints the message to stderr and returns `e.exit_code`.
  - `main(argv=None)`: normalizes `argv = sys.argv[1:] if argv is None else argv`; if `argv and argv[0] == "export"`, returns `_export_main(argv[1:])` before any preflight.
  - Run parser gains `--export` (`store_true`, help: `after a successful run, write a Playwright test to runs/<id>/duckwright.spec.ts`) and an epilog: `To turn an earlier run into a test: duckwright export runs/<id>`.
